# Task 122: bug: Dashboard tokens-mode chart contradicts the Total-tokens tile (plots uncached input only)

- **Type:** fix
- **Source:** GitHub issue #122
- **State:** OPEN
- **Labels:** none
- **Created:** 2026-07-25

## Description


## Symptom

On the Dashboard, the "Cost over time" chart in **tokens** mode and the **Total tokens** stat tile disagree by orders of magnitude, which reads as a data bug. With `?range=1d` on real data, the chart tooltip's Input-tokens value is a tiny few-digit number while the tile shows a total in the millions for the same window. Nothing on the page explains that the two widgets define "tokens" differently.

## Repro

1. `npm run dev`, open `http://localhost:4129/?range=1d` (any range with real Claude Code activity works).
2. On "Cost over time", click the **tokens** unit toggle.
3. Hover any bucket: the tooltip's Input/Output values sum to a tiny fraction of the "Total tokens" stat tile directly above.

## Expected vs actual

- **Expected:** the tokens-mode chart's total visibly reconciles with the Total-tokens tile, and the composition (cache reads dominate) is legible.
- **Actual:** the chart plots only `inputTokens` + `outputTokens`; the tile sums all four token measures. The dominant `cacheReadTokens` volume is invisible on the chart, and a few-digit "Input tokens" reading for a full day of use looks impossible.

## Evidence — settled during the 2026-07-25 investigation (do NOT re-litigate)

Both numbers are **correct**; this is a presentation bug, not a calculation bug. Verified by independently re-summing raw `~/.claude/projects/**/*.jsonl` transcripts (deduped by `message.id`, same as the ingest pipeline) and comparing to `/api/metrics` output — exact match, bucket for bucket.

1. **The tiny Input-tokens value is genuinely what Anthropic reported.** The API's `usage.input_tokens` field counts only the prompt slice that was neither read from nor written to the prompt cache. Claude Code caches essentially the whole conversation, so per-call `input_tokens` is typically single-digit (just the newest tokens past the cache breakpoint) while the real context volume lands in `cache_read_input_tokens` / `cache_creation_input_tokens` — with a ~95% cache hit rate, cache reads are roughly 95% of all token volume. Summing the four usage fields per day from the local transcripts reproduces the tile's total exactly; the chart's Input/Output series match the raw `input_tokens`/`output_tokens` fields exactly. Both widgets are faithful to the data.
2. **The tile deliberately sums all four measures** — `client/src/pages/dashboard/StatCardsRow.tsx` (`combinedTotal([input, output, cacheRead, cacheCreate])`, tile rendered around line 388).
3. **The chart deliberately excludes the cache measures** — `client/src/charts/units.ts` `UNIT_MEASURES.tokens = ["inputTokens", "outputTokens"]`, with a comment citing an "ARCH Open Questions, resolved default". Those ARCH docs are archived to the wiki; **no live spec mandates input+output-only** (checked `specs/claude-lens-pages.md` §1 lines 56–57 — "total tokens" and the cost-over-time chart carry no composition constraint; §Cache Lab line 137 even has an "X% served from cache" precedent).
4. Corroborating on-page signals that cache reads dominate: the Cache hit % tile and Cache leverage stat sit in the mid-90s% / double-digit-x range whenever the chart looks "broken".

## Root cause

Two widgets on the same page use different subsets of the four token measures with no labeling of either choice. Secondary latent issues found on the same path: (a) ChartCard's data table keys columns by the series group label, so the multi-measure tokens mode collapses all series into one last-write-wins "All" column (`client/src/charts/ChartCard.tsx`, `bucketRows`/`seriesLabelsKey`); (b) the Trends calendar heatmap reads only `series[0]`, so its tokens mode silently plots `inputTokens` alone (`client/src/charts/calendar.ts` `buildCalendarHeatmapOption`).

## Proposed fix (design already user-approved on 2026-07-25)

1. **`client/src/charts/units.ts`** — `UNIT_MEASURES.tokens` → `["inputTokens", "outputTokens", "cacheCreateTokens", "cacheReadTokens"]`. Array order is the ECharts stack order (engine emits series in `query.measures` order, `server/metrics/engine.ts` ~455): small fresh series at the baseline, dominant cache-read band on top.
2. **`client/src/charts/timeseries.ts`** — extend `stacked` to the area family (`stack: "total"` alongside `areaStyle`); `lines` never stacks; suppress the `compareGhost` overlay when stacked (absolute-valued ghost over cumulative bands reads at the wrong magnitude). The only pre-existing `stacked: true` caller (Trends `StackedWeeklyBarsPanel`) never requests compare, so no behavior is lost.
3. **`client/src/charts/ChartCard.tsx`** — pass `stacked: unit === "tokens"` to `buildTimeseriesOption` (`$`/`calls` are single-measure, unchanged); export `seriesName` from `timeseries.ts` and key `bucketRows`/`seriesLabelsKey` by it to fix the data-table column collision.
4. **`client/src/pages/dashboard/StatCardsRow.tsx`** — add `sub` pass-through on `DrillStatCard` (StatCard already supports `sub`; fold it into the Link's `aria-label` since the anchor label overrides descendant text) and render `"NN% cache reads"` = `cacheReadTotal / tokensTotal` on the Total-tokens tile, guarded against 0-token ranges. Note: deliberately a different denominator from the Cache-hit-% tile's `cacheRead / (input + cacheRead + cacheCreate)` — the two percentages will not match and must not be "unified".
5. **`client/src/charts/calendar.ts`** — sum aligned points across all series per day (buckets align within one query, decision A5), so the Trends calendar tokens mode shows total tokens/day.
6. **Do NOT touch `shared/metrics-contract.ts`** — `MEASURES` is pinned to 19 in its test; all four token measures already exist and are already fetched by both call sites.
7. **Tests:** update `client/src/charts/timeseries.test.ts` (`UNIT_MEASURES.tokens` expectation), `ChartCard.test.tsx` (two measures-array expectations), `CalendarHeatmapPanel.test.tsx` (measures expectation); add cases for area stacking, lines-never-stack, ghost suppression under stacking, tokens-mode stacked vs `$` unstacked, data-table measure-label columns, calendar multi-series sum, and a new `StatCardsRow.test.tsx` for the sub line (present with data, absent when the range has 0 tokens — no "NaN%").

A candidate implementation of exactly this design existed **uncommitted in the working tree** when this draft was written (2026-07-25), passing the full `npm run verify` gate and verified visually against live data (the tile's sub line renders, and the stacked chart's top edge matches the tile's total). If it's still present, review and use it; if discarded, reimplement per the list above.
