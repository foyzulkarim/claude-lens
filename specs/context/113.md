## Notes

### Diagnosis (2026-07-23)

The reported crash is a **symptom**; the defect is session attribution.

Claude Code no longer writes sub-agent (sidechain) activity inline in the
parent transcript — it writes one file per agent to
`<session-uuid>/subagents/agent-<id>.jsonl`. Measured on this machine:
**0 of 109** transcripts carry inline `isSidechain` lines, while 14 sessions
have a `subagents/` directory holding **67** agent files.

Discovery's `**/*.jsonl` glob picked those up and `classifyFilename` keyed
each by its **filename stem**, so every agent file became its own top-level
store session (`agent-<id>`), while every line inside carried the **parent**
session's `sessionId` (verified **67/67**).

Consequences:

1. **The reported crash.** `build-search-snapshot.ts` scoped its
   `occurrences` map per store session but built ids from
   `prompt.sessionId`. Two store sessions contributing the same
   `prompt.sessionId` each emitted occurrence 0 → identical
   `sessionId:promptId` id → MiniSearch rejected the whole index.
2. **~37% phantom sessions** — 67 of ~180 store sessions did not exist,
   and their cost/tokens were attributed to them instead of the real parent.
3. **The `main`/`sidechain` dimension was silently inert.** `dimensions.ts`,
   gate C3's sidechain exclusion, `cache/classifier.ts`, and
   `derive-turns`' `promptId::side|main` keying were all receiving zero
   sidechain rows.

### Resolution

Scope was deliberately merged into this issue (crash + attribution +
`turnNumber`) rather than split.

- **Route at discovery/ingest** — new `classifyPath()` maps
  `<uuid>/subagents/agent-<id>.jsonl` to `{sessionId: <uuid>, agentId: <id>}`.
  Downstream consumers needed **no changes**: they already branch on
  `isSidechain` within a session. `turnNumber` becomes correct as a
  consequence, since sidechain prompts now resolve against the parent's turns.
- **Reset semantics** — a session is no longer 1:1 with a file, and
  `resetSession` clears the whole session. The pipeline keeps a
  session → files index and replays sibling files after a truncation, so one
  agent file shrinking can't drop the parent's records.
- **`setTranscriptPath` pinned to the parent** via the `agentId` marker, so a
  late-registering agent file can't redirect Session Detail's deep link.
- **Defensive backstop** — `occurrences` hoisted to function scope in
  `build-search-snapshot.ts`, making the uniqueness guarantee its comment
  already claimed true by construction.

### Verified against real data

- Phantom `agent-*` sessions: **0** (was 67).
- Search docs 1127, **0 duplicate ids** (was: index failed to build).
- Session `84509ee5…`: 50 calls = 35 main + 15 sidechain, previously split
  across the parent and 10 phantom sessions.
- `npm run verify` green — 1600 tests (+11).

Not changed: cross-file `message.id` dedupe. The tailer dedupes per file, and
parent/subagent files were measured to have **zero** `message.id` overlap.
