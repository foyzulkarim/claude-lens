## Manual verification steps (T2 — FilterBar UI, hooks, and wiring)

Implementation for both tasks (T1 pure state, T2 UI/hooks/wiring) is complete —
`npm run verify` is green (266 tests, typecheck/lint/format clean). T2's
verification mode is `ui`, so it needs a human pass through the app before
being marked done in `specs/architecture/ARCH-filter-bar-url-sync.md`.

### Start the app

```bash
# terminal 1 — backend, pointed at the synthetic fixture dataset so the
# chips have real data to show (one project: "alpha")
npx tsx watch server/cli.ts --port 4128 --no-open --roots test/fixtures

# terminal 2 — client dev server (proxies /api and /ws to :4128)
npx vite --config client/vite.config.ts --port 5173
```

Open **http://127.0.0.1:5173/**.

### Checklist

1. **Filter bar renders** — Dashboard shows a bar above the page: `1D 7D 30D
   90D Custom` buttons, then 4 chip dropdowns (`Project`, `Model`, `Branch`,
   `Host`). `7D` is selected by default.

2. **Preset click updates the URL** — click `30D`. URL becomes `?range=30d`;
   `30D` now looks selected instead of `7D`.

3. **Chip lazily loads options** — open DevTools → Network, filter by
   `metrics`, clear the log. Click the `Project` chip.
   Expected: exactly one new `POST /api/metrics` request fires at that
   moment (not before), and the dropdown shows an option like
   `/Users/demo/projects/alpha`.

4. **Selecting a chip value updates the URL** — with the dropdown open,
   check that project's checkbox. URL gains `&project=...`; the chip button
   now reads `Project (1)`.

5. **Paste-URL reproduces the view** — copy the full URL, open a new tab,
   paste it in. Expected: `30D` and `Project (1)` are already selected on
   load, matching the copied URL.

6. **Filters survive navigation** — in the first tab, click `Sessions` then
   `Dashboard` again. Expected: `?range=30d&project=...` is still in the URL
   and still reflected in the bar.

7. **Host chip placeholder** — open the `Host` chip. Expected: the only
   option listed is `default` (real per-host data isn't wired up yet — this
   is documented, not a bug).
