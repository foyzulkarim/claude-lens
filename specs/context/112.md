# Task 112: feat: ship producer side of premium cost-capture tier

- **Type:** feat
- **Source:** GitHub issue #112
- **State:** OPEN
- **Labels:** enhancement,phase-4
- **Created:** 2026-07-23

## Description


## What & why

Phase 4 built the premium cost-capture tier **parser-first**: `server/ingest/parse-premium.ts` and the Data Health reconciliation read three sidecar formats that upgrade a session from computed (🟡) to observed (🟢):

- **C** — `<uuid>.cost.jsonl` (per-line cost samples)
- **B** — `<uuid>.turn-boundaries.jsonl` (Stop-hook turn ends)
- **L** — `~/.claude/cost-log.jsonl` (per-session totals)

But the **producer** side — the scripts that actually *write* these files — was never authored or vendored into the repo. As a result `client/src/pages/settings/CostCaptureGuide.tsx` instructs the user to "copy `cost-logger.js` + `turn-logger.js`", yet those files exist **nowhere in the repo**. During self-testing the setup guide reads as vague precisely because it points at phantom files. Working versions of these scripts live on another machine's `~/.claude`; this issue vendors them in and wires the guide to real paths, closing the tier system end-to-end so the 🟡→🟢 upgrade is actually reproducible by a user.

## Scope

1. **Vendor the real capture assets** into a new repo `capture/` directory (readable, pushed):
   - `cost-logger.js` — statusline wrapper: reads Claude Code statusline stdin, appends a line to `<uuid>.cost.jsonl` (C) and updates `~/.claude/cost-log.jsonl` (L), then execs the user's existing statusline so their statusline still renders. Must maintain per-session running state to emit `cost_delta_usd` / `cumulative_cost_usd` (statusline provides totals only).
   - `turn-logger.js` — Stop hook: reads hook stdin, appends a line to `<uuid>.turn-boundaries.jsonl` (B).
   - `settings.snippet.json` — copy-paste statusline wrapper + Stop hook wiring for manual users.
   - `README.md` — what each file does, the exact field contract, and how to verify capture is working.
2. **Add an idempotent `install.sh`** — timestamped backup of `~/.claude/settings.json`, non-destructive merge of the statusline wrapper + Stop hook, and copy of scripts to `~/.claude/scripts`. One command serves both the "let Claude run it" and "I'll do it myself" paths.
3. **Fix `client/src/pages/settings/CostCaptureGuide.tsx`** so its steps reference real paths (`capture/install.sh`, or "read then copy from `capture/`") instead of phantom files, keeping the existing live `captureSummary` verification readout intact.

## Acceptance

- [ ] A `capture/` directory exists in the repo with `cost-logger.js`, `turn-logger.js`, `settings.snippet.json`, and `README.md`.
- [ ] The emitted C/B/L files' field names match `server/ingest/parse-premium.ts` **exactly** (`session_id`, `cost_delta_usd`, `cumulative_cost_usd`, `api_duration_ms`, `context_pct`, `lines_added`, `lines_removed`, `cache_read_tokens`, `cache_write_tokens`, optional `prompt_id`, `turn`/`epoch`+`sample` for C; `session_id`, `transcript_path`, `turn_end`, `turn_end_epoch` for B; `session_id`, `timestamp`, `cost_usd`, `duration_ms`, `model`, `dir`, `context_pct`, `cache_read`, `cache_write`, `lines_added`, `lines_removed` for L) — filenames dot-separated per architecture §4.
- [ ] `install.sh` is idempotent (safe to re-run), backs up `settings.json` before touching it, and merges rather than overwrites existing hooks/statusline config.
- [ ] `CostCaptureGuide.tsx` names only paths/commands that exist in the repo; no phantom-file references remain. The live `captureSummary` "verified" readout still works.
- [ ] After running the installer on a machine and completing one session, Data Health / dashboard shows the session upgraded to observed (🟢).
