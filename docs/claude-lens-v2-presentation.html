The Product · 60 seconds

What is Claude Lens?

  • An observability dashboard for your own Claude Code usage — it tails the transcript files the CLI already writes and turns them into live metrics.
  • One npm package, one port: Fastify server + React SPA. Byte-offset incremental ingest, an in-memory metrics engine, WebSocket live-refresh.
  • 12 pages: Dashboard, Sessions, Turn Inspector, Cache Lab, Models, Trends & Budget, Report Card, Explore, Data Health…
  • A cost-tier system: 🟢 exact / 🟡 estimated from transcripts alone; optional capture files upgrade sessions to observed dollar costs.
  • Live on npm: npx @foyzulkarim/claude-lens — published Jul 21, mid-build.
The Objection

127K AI-generated lines. You're thinking: vibe code.

  • Specs merged before product code. PR #5 — specs, gates, and the phased plan — landed before a single feature line. The repo's rule: “Specs win over code or mockups.”
  • Gates existed before the product did. Phase 1 was CI, Biome lint/format, Storybook, strict TypeScript — merged before Phase 2 wrote the engine.
  • Every PR traces to a numbered plan task. #P0-2 through #P5-1. No orphan work, no mystery diffs.
  • Review actually bit. A revert (#68), a concurrency bug found under real load (#95), a sub-agent routing fix (#114) — real bugs, caught by real gates.
  • 2.4% deletion ratio. 3,141 deletions against 127K additions — what greenfield looks like when the plan is right the first time.
  • The 127K includes the safety net — Cypress E2E, Storybook, CI, fixtures. The tests aren’t omitted from the brag; they are the brag.

The Engine · github.com/foyzulkarim/skills

Not prompts — a pipeline

1
/plan-requirements
Socratic interview → REQ doc. Claude interviews; the engineer decides.
2
/plan-architecture
System design + change-footprint map → ARCH doc.
3
/generate-tasks
Slices ARCH into tasks, each with a verification mode: tdd · test-after · ui · checklist.
4
/implement
Executes each task under its verification discipline; commits per task.
5
/review
Triage-first: fans out up to 16 domain checks in parallel, one compiled report.
6
/commit
One-shot conventional commits with full diff context. Any stage.

Wrapped by lane management — /create-issue, /start-task, /move-to-worktree, /finish-worktree, /archive-issue — so the conveyor runs in parallel without collisions. Applied end-to-end across all 54 PRs.

The Thesis

The speed didn’t come from the model typing fast

Specs settle arguments
Written and merged first, binding over code and mockups. Every decision made once — no agent re-litigates it mid-build.
Gates make “done” objective
Typecheck, lint, format, tests, E2E — enforced on every push. An agent that can’t argue with the gate ships quality by default.
Lanes make agents additive
Isolated worktrees, ports, and gate runs mean four agents on a Saturday multiply output instead of stepping on each other.

The skills made the pipeline. The pipeline made the 21 days.
